# 自作カレンダーアプリ

Google カレンダーの予定を、種類ごとに色分けして表示する個人用の PWA。
公開先： <https://daifuk00003-alt.github.io/my-calendar/>

要件定義書は `docs/calendar-requirements.pdf`。実装を進める中で要件から変えた点は
「**要件定義書からの変更**」にまとめてある。

---

## 1. 仕組み

**アプリ側で Google ログインを行わない。**
本人の Google アカウント上に置いた Apps Script が「本人として」カレンダーを読み書きし、
アプリはその Apps Script に問い合わせる。

```
iPhone のホーム画面アプリ
      ↓ URL + 鍵
Apps Script（本人として動く）
      ↓
Google カレンダー
```

はじめは OAuth でブラウザから直接 Google API を叩いていたが、アクセス権が1時間で切れ、
iPhone の Safari が他サイトの Cookie を遮断するため裏での取り直しも通らず、
**開くたびにログインを求められた**。それを解消するためにこの形にした。

## 2. 準備

### 2-1. Apps Script を置く

1. `docs/apps-script.gs` の中身をコピー
2. <https://script.google.com/home/projects/create> で新規プロジェクトを作り、貼り付けて保存
   - **カレンダーが見えるアカウントで作る**こと（共有されたカレンダーもそのアカウントから見える必要がある）
3. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
   - **次のユーザーとして実行：自分**
   - **アクセスできるユーザー：全員** ← ここが「自分のみ」だとアプリから呼べない
4. 承認を求められたら許可する（「このアプリは確認されていません」→ 詳細 → 移動）
5. 出てきた `.../exec` の URL を控える

> **URL と鍵の両方を知っている相手はカレンダーを読み書きできる。**
> URL は推測できない長い文字列で、鍵が一致しないとスクリプトは何も返さないが、
> この2つはパスワードと同じ扱いで管理すること。

### 2-2. アプリにつなぐ

アプリを開くと URL と鍵の入力欄が出る。2-1 の URL と、`apps-script.gs` の `KEY` を入れて「つなぐ」。
端末内にだけ保存され、**以後ログインは不要**。端末ごとに1回だけ必要。

### 2-3. ホーム画面に追加

- iPhone: Safari で開く → 共有 →「ホーム画面に追加」
- Android: Chrome → メニュー →「アプリをインストール」

## 3. 色ルールを自分の予定に合わせる

`js/color-rules.json` を編集する。

```json
{
  "categories": [
    { "id": "aiplus", "label": "AIプラス", "color": "#ec4899" }
  ],
  "rules": [
    { "keyword": "【AIプラス】", "category": "aiplus" }
  ]
}
```

- `categories` の並び順が、追加フォームの種類ボタンの並び順になる
- `rules` は**上から順に評価し、最初に一致した色**を採用する（FR-14 先勝ち）
- 判定は**タイトルの部分一致**（FR-12）。全角/半角・大文字小文字は自動で揃える（FR-13）
- どれにも当たらない予定は**グレー**（FR-15）
- 2つ以上に当たると**●印**が付く（FR-16）
- **`【 】` で囲んだキーワードは「本人が付けた印」**として扱い、●印を出さない
- **先頭の `【 】` は画面に表示しない**（色が種類を伝えるので文字としては不要）。
  Google 側のタイトルには残る（印がないと次に開いたとき色が決まらないため）
- 色数に上限はない。8色を超えると起動時に警告が出る（凡例なしで見分けられる限界のため）

`categories` を増やしたり名前を変えたら、**`【名前】` のルールも合わせて直すこと。**
種類ボタンは `categories` から作られ、選ぶと `【label】` が予定名の先頭に付く仕組みのため。

### 反映のしかた

- **手元（`localhost`）**：保存してリロードするだけ。通信も再取得もしない
- **公開版**：以下を実行すると1分ほどで反映される

```bash
cd "/Users/d/Library/Mobile Documents/com~apple~CloudDocs/AI作品全て/my-calendar" && git add -A && git commit -m "色ルール更新" && git push
```

## 4. 操作

| 操作 | 動作 |
| --- | --- |
| 上部の `2週間` `1ヶ月` | 表示の切り替え。既定は2週間。選択は端末に記憶される |
| 左右スワイプ / `‹` `›` | 前後へ移動（2週間ずつ／1ヶ月ずつ） |
| 日付をタップ | その日の予定を下部に表示 |
| 予定をタップ | その場で編集（種類・予定名・時刻） |
| 予定を左スワイプ | 削除ボタンが出る。確認のうえ削除（Google のゴミ箱に入る） |
| メモをタップ | メモの全文を表示 |
| 右下の `＋` | 予定を追加 |
| 下に引っ張る | 手動で最新データを取得 |
| 右上 `☰` | 取り込むカレンダーのオン/オフ、色ルールの凡例、バックアップ、接続の解除 |

開いたとき・他アプリから戻ったときに自動で最新データを取得する（FR-03）。
定期ポーリングやプッシュ通知は行わない（FR-05）。

### 予定を追加・編集するときの入力

- **種類（色）**：ボタンで選ぶ（必須）。予定名の先頭に `【AIプラス】` のような印が付く
- **日付**：入力欄なし。月表示で選んでいる日に入る。見出しに「8月3日(月) に追加」と出る
- **開始 / 終了**：開始を動かすと、それまでの所要時間を保ったまま終了もずれる
- **メモ・追加先カレンダー**：欄を置いていない。メモは Google 側で書く（表示はする）

## 4-1. バックアップについて（重要）

**予定は、いま接続しているアカウント（Apps Script を置いたアカウント）の中に保存されている。**
そのアカウントが使えなくなれば（退職・解約・削除など）、予定も一緒に失われる。
このアプリ自体は予定を複製・保管する仕組みを持たないため、**定期的に手元へ書き出しておく必要がある。**

設定画面（☰）の **「予定をバックアップする（.ics）」** を押すと、全カレンダーの予定
（既定で3年前〜1年後の範囲）を書き出せる。iPhone では `.ics` を Safari が
**Apple の「カレンダー」アプリへの取り込み**として扱うため、ボタンを押すと
「すべて追加」の画面が出る。ここで実際に取り込めば、**Apple 側（iCloud）に実体のコピーが残り、
Google の会社アカウントが使えなくなっても消えない。**

**取り込み先は、会社アカウントと同期していないカレンダーを選ぶこと。**
あらかじめ Apple の「カレンダー」アプリで `iCloud` 配下に専用のカレンダー
（例：「バックアップ」）を作っておき、毎回そこへ取り込むと安全。

**バックアップは「その場の全件コピー」であって、以後の更新を追いかける仕組みではない。**
くり返し実行すると、そのたびに全件が新規として追加され重複する。
月イチなど定期的に行う場合は、前回分を消してから取り込むか、重複は気にせず
「記録として残っていればよい」と割り切るとよい。

**もう1点、根本的な注意点がある。** いま「＋」で追加した予定は、書き込みできるカレンダーが
1つしかないため、**接続に使っているアカウント（会社のアカウントなど）のカレンダーに保存される。**
そのアカウントを失うことを心配しているなら、新しく追加する予定は本人が恒久的に持つ
アカウント側に保存されるようにする方が筋が良い。これは以下が必要になる。

1. 保存したい側のカレンダーを、現在のアカウントに「予定の変更権限つき」で共有し直す
2. アプリが正しく書き込み先を選べるよう、判定ロジックを直す

上記は今後の課題として残っている（`js/app.js` の `targetCalendarId()` 付近）。

## 5. ファイル構成

```
my-calendar/
├── index.html            画面の骨格
├── manifest.json         PWA 設定
├── sw.js                 Service Worker（毎回ネットワークから取り直す）
├── css/style.css         見た目。分割比率・文字サイズはここ
├── icons/                アイコン
├── docs/apps-script.gs   裏方のコード（公開リポジトリには含めない）
└── js/
    ├── app.js            全体の制御・描画
    ├── gas.js            Apps Script との通信
    ├── classify.js       色分けロジック
    ├── color-rules.json  色ルール（編集する場所）
    ├── colors.js         背景色から読める文字色を決める
    ├── store.js          端末内ストレージ（接続先・キャッシュ・設定）
    ├── dates.js          日付ユーティリティ
    ├── config.js         接続先、バー本数などの調整値
    └── demo.js           ?demo=1 用のダミーデータ
```

`?demo=1` を付けて開くと、ダミーデータで表示だけ確認できる（通信しない）。

## 7. 要件定義書からの変更

すべて実際に使ってみた結果の判断。元に戻せるものは戻し方を書いてある。

**FR-01 / PRE-04 / NFR-06（OAuth・読み取り専用）**
→ Apps Script 経由に変更し、アプリ側の Google ログインを廃止。追加・編集・削除ができる。
毎回ログインを求められる問題（CON-02）が実用上つらく、他に解消手段がなかったため。

**3.2（予定の作成・編集・削除は作らない）**
→ **追加・編集・削除を実装**した。日付の変更とメモの編集は扱わない。

**FR-26（タップで Google 公式アプリを開く）**
→ **取りやめ。**タップでその場の編集フォームを開く。直したいだけなのに毎回アプリが
切り替わって煩わしかったため。

**FR-23（詳細は「時刻」と「メモ」）**
→ **予定タイトルを表示し、それを主役にする。**メモのない予定が時刻だけの行になり、
何の予定か判別できなかった。時刻は補助情報として小さく出す。

**FR-22（月表示のバーに文字を載せない）**
→ **バーに予定名を載せる。**あわせて上下の分割比率を月表示側へ寄せた（64:36）。
月表示がうるさく感じたら `SHOW_TITLE_IN_MONTH` を `false` に戻して比較する。

**FR-20（上：月表示）**
→ 既定を**2週間表示**にし、上部のボタンで1ヶ月表示に切り替える。
1ヶ月を6行に詰めると1マスが低く、予定名を載せると3件で埋まってしまうため。
2週間なら1日8件まで名前付きで並ぶ。月表示の行数もその月が占める週数（4〜6週）に合わせる。

**FR-17（色は4色まで）**
→ **上限をなくした。**いまは7種類。月表示のラベルに載せる文字色は、背景の明るさから
白か濃色かを自動で選ぶ（黄色や水色でも読めるように）。

## 9. 困ったときは

**「更新できませんでした」と出る**
Apps Script の公開設定（アクセスできるユーザー＝全員）を確認する。
`docs/apps-script.gs` を直したあとは、**デプロイし直さないと反映されない**
（デプロイ → デプロイを管理 → 鉛筆 → バージョン「新バージョン」→ デプロイ）。

**予定が `(タイトルなし)` になる**
そのカレンダーの共有設定が「予定の時間枠のみを表示」になっている。
共有元で「すべての予定の詳細を表示」に変える。タイトルが読めないと色分けもできない。

**更新したのに画面が古いまま**
Service Worker が毎回ネットワークから取り直す設定にしてあるので、通常は開き直せば直る。
